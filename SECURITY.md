# Security and data handling

The browser analyzes recordings in memory. It does not upload imports to a remote backend. The optional archive is a single-user local service, with bounded JSON bodies, schema validation, parameterized SQLite queries, restricted hosts and cross-origin POST rejection. It does not provide authentication, tenant isolation, encrypted storage or fleet management. Bind it to loopback and protect the host filesystem; do not expose it directly to the internet.

Traces may reveal application names and vehicle observations. Review recordings before sharing them. Repository fixtures are synthetic. Android uses a bounded memory buffer and explicit file export; it records no microphone or GPS data. Cleartext HTTP is allowed only for the emulator/loopback development hosts in its network security configuration.

Do not commit recordings from your employer, university or customer, API keys, signing keys or production device identifiers. To report a vulnerability, use GitHub's private vulnerability reporting if enabled, or contact the maintainer through the profile's published contact method. Do not place sensitive payloads in public issues.
